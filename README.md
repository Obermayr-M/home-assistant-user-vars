# User Variables for Home Assistant

![User Variables icon](custom_components/user_vars/brand/icon.png)

[![GitHub Release](https://img.shields.io/github/v/release/Obermayr-M/home-assistant-user-vars?display_name=tag)](https://github.com/Obermayr-M/home-assistant-user-vars/releases)
[![HACS Validation](https://img.shields.io/github/actions/workflow/status/Obermayr-M/home-assistant-user-vars/validate.yml?label=validation)](https://github.com/Obermayr-M/home-assistant-user-vars/actions)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

**User Variables** is a custom integration that provides persistent, typed, user-specific variables for authenticated Home Assistant users.

Define a variable once and keep an independent value for every Home Assistant user. This avoids creating one helper, script, or automation per user in large shared installations.

> [!IMPORTANT]
> User Variables is a state-storage component, not an authorization system. For doors, gates, locks, alarms, or other security-sensitive equipment, validate permissions, request age, location, device state, and replay protection in the consuming automation.

## Features

- Persistent values stored with Home Assistant's storage API
- Automatic scoping to `context.user_id`
- Boolean, string, integer, and number types
- Configurable defaults
- Add, edit, and delete definitions from the Home Assistant UI
- English and German UI
- Timestamp on explicit user values
- User-facing actions: `set`, `get`, `toggle`, `clear`
- Administrative/internal actions: `list_values`, `clear_for_user`
- Automatic cleanup of user values when a definition is deleted

## Installation

### HACS custom repository

1. Open HACS / Marketplace.
2. Add `https://github.com/Obermayr-M/home-assistant-user-vars` as a custom repository of type **Integration**.
3. Search for **User Variables** and install it.
4. Restart Home Assistant.
5. Go to **Settings → Devices & services → Add integration → User Variables**.

### Manual

Copy:

```text
custom_components/user_vars/
```

to:

```text
/config/custom_components/user_vars/
```

Restart Home Assistant and add **User Variables** from **Settings → Devices & services**.

Only one integration instance is intended per Home Assistant installation.

## Create a variable

Open:

```text
Settings → Devices & services → User Variables → Configure
```

Choose **Add variable** and define:

- **Variable key**, for example `garage_request`
- **Display name**, for example `Garage Request`
- **Data type**: Boolean, String, Integer, or Number
- **Default value**, for example `false`

The key and data type are intentionally immutable after creation. The display name and default can be edited.

## Actions

All actions return response data. User-facing actions require a logged-in Home Assistant user context.

### `user_vars.set`

```yaml
action: user_vars.set
data:
  key: garage_request
  value: true
```

### `user_vars.get`

```yaml
action: user_vars.get
data:
  key: garage_request
response_variable: garage_request_state
```

Example response:

```yaml
user_id: 0123456789abcdef0123456789abcdef
key: garage_request
value: true
is_default: false
updated_at: "2026-11-25T00:25:07.947869+01:00"
```

### `user_vars.toggle`

Boolean variables only:

```yaml
action: user_vars.toggle
data:
  key: garage_request
```

### `user_vars.clear`

Removes the explicit value for the calling user. The effective value falls back to the definition's default.

```yaml
action: user_vars.clear
data:
  key: garage_request
```

### `user_vars.list_values`

Administrator or internal automation only. Returns all explicitly stored values for one key. Users relying on the default are not included.

```yaml
action: user_vars.list_values
data:
  key: garage_request
response_variable: garage_requests
```

### `user_vars.clear_for_user`

Administrator or internal automation only.

```yaml
action: user_vars.clear_for_user
data:
  user_id: 0123456789abcdef0123456789abcdef
  key: garage_request
```

## Storage

Data is managed by Home Assistant in:

```text
/config/.storage/user_vars
```

Do not edit this file manually.

```json
{
  "definitions": {
    "garage_request": {
      "name": "Garage Request",
      "type": "boolean",
      "default": false
    }
  },
  "users": {
    "0123456789abcdef0123456789abcdef": {
      "garage_request": {
        "value": true,
        "updated_at": "2026-11-25T00:25:07.947869+01:00"
      }
    }
  }
}
```

## Garage request example

The original use case is a shared residential Home Assistant installation where residents request garage opening before arrival. The integration stores the per-user request; a separate automation validates Person and Device Tracker data, request age, distance, and GPS accuracy before operating the gate.

See [`examples/garage_request`](examples/garage_request/README.md). The example is intentionally generic and contains placeholder entities that must be adapted.

## Limitations

- No per-user entities are created, so frontend cards cannot directly react to a personal value without an additional presentation layer.
- Keys and types cannot be changed after creation.
- No built-in TTL or expiration. Consuming automations should use `updated_at` and clear expired values.
- `list_values` and `clear_for_user` permit internal calls without a user context so scheduled automations can process requests. Treat automations using these actions as privileged configuration.
- This project is not part of Home Assistant Core and is not officially supported by the Home Assistant project.
